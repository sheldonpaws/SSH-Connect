# SSH-Connect

**SSH-Connect** — настольный SSH-клиент для Windows, созданный для подключения к Linux-VPS. Это приложение на Python + Tkinter, которое управляет встроенной копией **KiTTY** (`kitty.exe`) и дополнительно запускает **веб-интерфейс** (FastAPI) после подключения.

Интерфейс и строки приложения — на русском языке. Проект ориентирован на комфортную работу в связке с **tmux** и **веб-интерфейсом** прямо с сервера.

---

## Возможности

- **Графический интерфейс** — тёмная тема «бархатно-чёрный + сиреневый», профили подключений с сохранением паролей (шифруются Fernet).
- **Встроенный терминал KiTTY** — пароль и команды с кнопок отправляются через Win32 `PostMessage` WM_CHAR (никогда не попадают в командную строку), работают даже со свёрнутым окном.
- **Веб-интерфейс** — автоматически запускается после подключения: файловый менеджер (загрузка/скачивание, включая большие файлы и папки через `tar`), список установленных утилит, запуск программ.
- **Управление tmux** — переключение, создание и удаление сессий прямо из главного окна.
- **Четыре дополнительных окна терминала** — список «Окно:» со слотами 2–5 (фиксированный, не растёт). Выбор слота открывает или показывает окно KiTTY, а новая сессия tmux автоматически создаётся в первом свободном окне. Основное окно 1 работает как раньше.
- **Обратный доступ (Reverse Access)** — открывает выбранные папки Windows серверу через обратный SSH-туннель на порту `17850` (несколько папок на одном порту).
- **Скилл Hermes на сервере** — после подключения тихо ставится локальный скилл `reverse-ssh-tunnel` (`~/.hermes/skills/devops/`), чтобы агент на VPS знал, как пользоваться обратным доступом. Веб-чата с агентом в приложении нет.
- **Docker-браузер** — кнопка в веб-интерфейсе (вместо RDP): проверяет на сервере наличие `docker` и контейнера `linuxserver/chrome`. Если их нет — показывает список команд для ручной установки (с кнопкой «копировать»); приложение само на сервере ничего не ставит. Когда всё готово, открывает страницу `https://<хост>:3001` в новой вкладке.
- **Прокрутка истории tmux мышью** — утилита `move_cursor` конвертирует PgUp/PgDn в колесо прокрутки.

## Установка и запуск

Требуется **Python 3.13** (используется виртуальное окружение `SSH_env`).

```bash
# 1. Установить зависимости
python -m venv SSH_env
SSH_env\Scripts\pip install -r requirements.txt

# 2. Запустить приложение
python main.py          # с консолью
python main.pyw         # без консоли
```

Веб-интерфейс обычно запускается автоматически из GUI после подключения. Автономный запуск:

```bash
cd web-desktop\backend
python main.py          # uvicorn на http://127.0.0.1:8000 (reload=False)
```

Сборка фронтенда не требуется — vanilla JS без шага сборки.

> **Примечание:** тесты — стандартный `unittest` (`run_tests.py`), офлайн, без VPS. Линтера и CI нет. Также полезна проверка `python main.py` — GUI запускается без ошибок.

## Краткая архитектура

```
main.py / main.pyw / ssh_client.py  →  src.gui.SSHApp
```

| Модуль | Назначение |
|---|---|
| `src/gui.py` | Главное окно (Tkinter) + `KittyController` (управление KiTTY через Win32) |
| `src/ssh.py` | SSH-подключение (paramiko) и reverse-туннель |
| `src/reverse_access.py` | Обратный доступ: файловый сервер папок Windows на порту `17850` |
| `src/encryption.py` | Шифрование сохранённых паролей (Fernet) |
| `src/hostkeys.py` | Проверка host-key (защита от подмены) |
| `src/hermes_skills.py` | Авто-установка скилла `reverse-ssh-tunnel` на сервер (файл генерируется) |
| `web-desktop/backend/` | Веб-интерфейс (FastAPI): файлы, программы, запуск в KiTTY |
| `web-desktop/backend/docker_manager.py` | Docker-браузер: проверка `docker` + контейнера `chrome`, команды ручной установки, порт `3001` |
| `move_cursor.py` | PgUp/PgDn → колесо прокрутки (низкоуровневый хук Win32) |

**Терминал — не часть Tkinter.** Это `kitty.exe` (KiTTY). Главное окно управляет им через Win32, а сам терминал отрисовывается отдельно.

## Безопасность

- Пароли шифруются **Fernet**; ключ лежит вне репозитория — `%APPDATA%\SSH-Connect\.encryption_key`. Никогда не удаляйте его (обесценит все профили).
- Передача команд в KiTTY — только через `PostMessage WM_CHAR`, **не** через командную строку.
- Запуск KiTTY — список аргументов без `shell=True` (защита от cmd-инъекции через имя пользователя/хоста), имена строго валидируются.
- Веб-интерфейс: токен авторизации — только в заголовке `X-Auth-Token`, защита от DNS-rebinding (принимает только `127.0.0.1`/`localhost`), `--no-access-log`.
- Обратный доступ защищён от path-traversal (`commonpath`).
- Docker-браузер не выполняет на сервере никаких установок и не требует пароля: бэкенд только проверяет готовность (без `sudo`), а команды установки показываются пользователю для запуска вручную.

```yaml
# структура репозитория
.gitignore, LICENSE, README.md   # отслеживаются
main.py, src/, web-desktop/, kitty.exe, build.bat  # не в gitignore
SSH_env/, user_data/, *.log, .server_token         # не коммитится
```

## Сборка (портативный exe)

`build.bat` собирает приложение через **PyInstaller** (onedir, windowed) в
`dist\SSH-Connect\`:

```
dist\SSH-Connect\
  SSH-Connect.exe      # сама программа (+ иконка в окне и на панели задач)
  _internal\           # ТОЛЬКО библиотеки (Python, DLL, зависимости)
  web-desktop\, skills\, kitty.exe, kitty.ini, move_cursor.py, favicon.ico ...
  Sessions\            # портативные настройки KiTTY (размер окна/шрифт)
  SSH_env\             # python + uvicorn/fastapi (move_cursor и веб-интерфейс)
  user_data\           # папка пользователя (создаётся и при первом запуске)
      ssh_connections.json, SshHostKeys\, Sessions\, Downloads\
```

- При первом запуске `.exe` автоматически создаётся ярлык на рабочем столе
  (если его ещё нет).
- KiTTY при подключении получает host-key через `-hostkey` — свой английский
  диалог про ключ не показывается.
- `build.bat zip` дополнительно упакует сборку в архив.
- Иконка окна/панели задач берётся из `favicon.ico`.
